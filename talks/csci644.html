Standard Evaluation Assumption

  • All tool calls are free and instant
  • Only the final answer quality is measured
  • More tool calls = better exploration = better answers
  • Models ranked on accuracy alone

Deployment Reality

  • A training run costs 30 sec to 14 hours
  • A document fetch costs ~5 minutes
  • Expert feedback costs ~5 minutes
  • The model thinks in milliseconds—the world is the bottleneck
2

The Expensive External Information Problem

Current benchmarks measure accuracy and speed, but ignore cost. We argue cost deserves equal attention. We call this the Expensive External Information (EEI) problem.

When every tool call has a real cost, the critical capability is no longer tool-use proficiency but cost-aware decision-making:

  • Is this query worth its price?
  • How should I allocate my remaining budget?
  • What do I do when budget runs out?
Under EEI, 5 well-chosen queries can outperform 50 mediocre ones—but cost-free benchmarks cannot detect which agent knows the difference.
Imagine researching at a pay-per-article library. With unlimited money, you'd read everything. With $9, you'd better pick your 3 articles very carefully.
3

Why Does EEI Matter?

If model rankings change when cost is introduced, three problems follow:

Wrong model gets deployed

The cost-free leaderboard winner may be the worst choice under a real budget. You pick a model based on benchmarks—and it fails in production.

Hidden failure modes

Cost-free evaluation can't reveal whether a model wastes budget, ignores constraints, or collapses under pressure. These problems only appear in deployment.

No way to measure it—until now

Testing at real-time speed would take months. We need a fast, reproducible framework to evaluate agents under cost pressure.

4

ExpGym: Fast Evaluation in Expensive Worlds

ExpGym is a pre-cached test suite that makes large-scale evaluation under cost pressure practical.

How It Works

Pre-cached Interactions

All tool call results are computed once and stored. The agent still makes its own decisions—only the environment's responses are replayed.

Simulated Budget Accounting

Each call deducts its real wall-clock cost from the agent's budget. If the agent overspends, the result is withheld—it paid but got nothing back.

Like a flight simulator: the world's responses are pre-recorded, so we can test a pilot's decisions without flying a real plane.

Three Expensive Worlds

Each world isolates a different type of costly interaction—optimization, retrieval, and verification:

Hyperparameter Tuning

Goal: Find the best configuration for a black-box ML model.

Tool: evaluate_config — submit parameters, get performance.

Cost: 29–50,264s per call (varies 1,700×).

Scale: 9 tasks across 3 families.

Metric: Gap Score (0 = random, 100 = best known).

Restricted Search

Goal: Answer questions requiring chaining across multiple articles (e.g., find X's grandmother).

Tool: search — query → article. Re-queries are free.

Cost: ~5 min per new article.

Scale: 5,000 fictional articles, 35 questions (3 retrieval steps each).

Metric: F1 (predicted vs. correct answers).

Evidence Audit

Goal: Classify legal hypotheses and find supporting evidence in contracts.

Tool: human_feedback — submit hypothesis + evidence, get verification.

Cost: ~5 min per verification.

Scale: 13 contracts, 17 hypotheses each.

Metrics: Label accuracy + Evidence accuracy.

6

Three Budget Levels

The budget is a multiple of the cheapest possible tool call. We test three levels:

Unlimited

Cost-Free

No spending limit. Cost is hidden from the agent. This is how most benchmarks work today.

10×

Cost-Moderate

Budget = 10× the cheapest call. Agent can complete most tasks, but must prioritize. Cost shown after each call.

3×

Cost-Tight

Budget = only 3× the cheapest call. Agent can afford roughly ~3 actions. Every call must count.

Over-budget rule: If the agent overspends, the result is withheld—the agent paid the cost but got nothing back, and must submit its answer immediately.

Result 3: Three Behavioral Classes

Why do rankings invert? Models fall into three groups based on how they handle budget pressure:

Winner under budget

Naturally Efficient

GPT-5.2

  • Uses only 7.6 tool calls on average (half what others use)
  • Under budget, reduces calls by just 30%—barely needs to change
  • Only 4% of runs terminated for overspending
  • Wins 4 of 7 families under tight budget
Sees it, can't fix it

Aware but Ineffective

Haiku-4.5, DSV3.2

  • Haiku slashes from 30 to 6.6 calls (78% reduction)—but still runs out
  • DSV3.2 mentions budget 68 times—but 96% of runs still terminated
  • Both talk about the budget, neither changes what they search for
Doesn't even notice

Budget-Blind

Gemini-3, Mistral, GPT-4.1

  • Gemini-3 produces zero budget mentions in its reasoning
  • 56–89% of runs terminated for overspending
  • No change in strategy—rigid until cut off
  • Some make up answers instead of searching

Key Insight: Awareness ≠ Adaptation

The critical gap is not whether a model notices the budget,
but whether it actually changes its behavior.
GPT-5.2 Naturally frugal → wins under budget without trying
DSV3.2 Mentions budget 68 times → 96% of runs still terminated
Gemini-3 Zero budget mentions → makes up plausible answers instead
A student who says "I should study more" every day but never changes their routine is aware of the problem—but awareness alone doesn't improve their grades.

Result 4a: Budget Exhaustion Dominates

Under Cost-Free, 85% of traces complete successfully. Under Cost-Tight, 65% fail because the agent ran out of budget:

Completed successfully 85% → 30%
Ran out of budget 0% → 65%
Wrong reasoning 10% → 2%
Format error 3–5% (constant)

Values: Cost-Free → Cost-Tight

Budget exhaustion replaces reasoning failure as the dominant failure mode. The bottleneck shifts from the model's own ability to its interaction with the world.
13

Result 4b: Each Scenario Fails Differently

Different scenarios expose different vulnerabilities:

Search: Most Sensitive

Only 42% of traces complete under budget pressure (vs. 61% tuning, 73% audit).

Multi-hop questions need 3+ article fetches, but a tight budget allows only ~3 total calls. The task itself requires nearly the entire budget.

Audit: Looks Fine, But Isn't

Models still get the labels roughly right, but the evidence supporting those labels collapses 2–10× faster.

The system appears to work but has silently lost its factual grounding—a dangerous form of degradation.

Tuning: Model-Specific

Each model fails for characteristically different reasons.

GPT-5.2 completes 77% of traces. Mistral has the highest reasoning failure rate (10%). DSV3.2 has the lowest completion (36%) due to format errors.

Models fail for diverse reasons—exhausting budgets, making up answers, or ignoring constraints. No single training fix generalizes across models and scenarios.
14

Key Takeaways

1. Cost-free leaderboards are structurally blind

The best model under free evaluation is systematically the wrong deployment choice under budget. Rankings reshuffled in all 7/7 task families.

2. Three behavioral classes explain the inversions

Naturally efficient, aware-but-ineffective, and budget-blind. These same classes recur across all scenarios—stable model-level properties invisible to cost-free evaluation.

3. Failures are diverse—no single fix works

Budget exhaustion dominates (0% → 65%), but models also make up answers, produce format errors, and degrade silently. No single training intervention addresses all failure modes.

The Third Evaluation Axis

Current agent evaluation measures two things. Our results argue for a third:

1.Accuracy — Does it get the right answer?
2.Latency — How fast does it respond?
3.Interaction Cost — How wisely does it spend?
ExpGym makes this third axis measurable and practical. Its 120× speedup turns month-long evaluations into single-day sweeps—serving as both an evaluation platform and a development sandbox for cost-aware agents.
16

Limitations & Future Work

Limitations

Simulated, not real-time costs

ExpGym deducts simulated time rather than imposing real waits. This prevents studying real-time adaptive strategies (e.g., an agent that plans while waiting).

Task and model coverage

Three scenarios, six models. Additional domains (e.g., code generation, web navigation) and model sizes may reveal different patterns.

Descriptive, not causal

Our failure analysis identifies behavioral patterns but does not test causal interventions (e.g., adding budget hints, training with cost rewards).

Future Directions

  • Can post-training (e.g., RL with budget-efficiency rewards) close the gap between aware-but-ineffective and efficient models?
  • Extend ExpGym to more domains and models, including open-weight models of varying sizes
  • Design causal interventions to test whether budget signals, triage heuristics, or cost-aware prompting can improve performance
  • Explore infrastructure-level solutions that coordinate multiple agents to share expensive observations
